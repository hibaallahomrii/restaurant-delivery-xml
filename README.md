# TP1 - XML Modelling & XPath Querying with Maven (Java)
### Domain: Restaurant / Meal-Delivery Platform

> **Course:** SOA Architecture & Web Services - LSI3 - Faculty of Sciences of Sfax (2025-2026)
> **Goal:** model a real domain in XML, validate it with an XSD, then query it with XPath - in a Maven project.

This repository is a complete, tested solution of TP1. It covers **everything required by the TP**
and adds several bonus features so the project is rich enough to impress.

### Bonus features (beyond the TP)

| Bonus | Description |
|---|---|
| **10 invalid XML files** | Each has ONE deliberate defect; the program proves the XSD rejects all of them (`src/main/resources/xml/invalid/`) |
| **51 ready-made XPath queries** | From `//dish/name` to joins, axes, union and "never ordered" dishes ([`QueryCatalog.java`](src/main/java/com/fss/soa/tp1/QueryCatalog.java)) |
| **Referential integrity in the XSD** | `xs:key` / `xs:keyref` = primary keys and foreign keys between orders, customers, restaurants, drivers, dishes |
| **Business-rule checker** | Rules an XSD cannot express (payment = items + fee, dish belongs to the restaurant...) verified with XPath in Java |
| **Order report** | A table built by combining several XPath queries |
| **Interactive XPath console** | Type your own expressions and see results instantly |
| **20 JUnit 5 tests** | Automatic verification of validation, XPath and business rules |
| **Generated reports** | `output/*.txt` files written on every full run |
| **Full documentation** | 6 guides in [`docs/`](docs/) |

## 3. Quick start

**Requirements:** JDK 8 or newer (tested with JDK 21). Maven is optional.

### Option A - with Maven (recommended, as asked by the TP)
```bash
mvn compile exec:java          # run the whole demonstration
mvn test                       # run the 20 JUnit tests
mvn package                    # build target/restaurant-delivery-xml.jar
java -jar target/restaurant-delivery-xml.jar            # run the jar
java -jar target/restaurant-delivery-xml.jar xpath      # only the XPath feature
```

### Option B - without Maven (plain JDK)
```bash
./scripts/run-without-maven.sh              # Linux / macOS / Git Bash
scripts\run-without-maven.bat               # Windows
```

### Option C - from IntelliJ IDEA
Open the folder as a Maven project, open `Main.java`, click the green arrow next to `main`.
(Details in [`docs/02-STEP-BY-STEP-GUIDE.md`](docs/02-STEP-BY-STEP-GUIDE.md).)

### Modes

```bash
java -jar target/restaurant-delivery-xml.jar [mode] [--xml file.xml] [--xsd file.xsd]
```

| Mode | What it does |
|---|---|
| *(none)* | Everything + saves reports into `output/` |
| `validate` | Feature 1 - validate the XML against the XSD |
| `xpath` | Feature 2 - run the 51 XPath queries + the order report |
| `rules` | Bonus - business rules R1..R5 |
| `suite` | Bonus - the 10 invalid files must all be rejected |
| `interactive` | Bonus - type your own XPath expressions |

You can validate **your own** file: `java -jar ... validate --xml C:\data\my.xml`.

## 5. How the three layers of checking fit together

```
 1. Well-formedness   -> is the XML syntax correct?            (the parser)
 2. XSD validity      -> structure, types, keys, references    (XmlValidator, feature 1)
 3. Business rules    -> cross-value logic (totals, ownership) (BusinessRulesChecker, bonus)
```

A document can pass 1 and fail 2, or pass 1 and 2 and still fail 3. The project demonstrates all three cases.
